# 自动测试

## 黑盒测试

### 黑盒测试

**黑盒测试**：是一种不考虑程序内部代码和逻辑结构，仅根据功能需求规格说明书来验证软件功能是否符合预期的方法

### 测试方法

- 边界值分析法：针对临界点及临近区域设计测试用例
- 等价类划分法：将所有可能的输入数据划分为若干个有效和无效的等价类，从每个类中抽取代表性数据测试

## CTest

CTest 是 CMake 集成的一个测试工具

**添加测试**

```cmake
add_test(
    NAME <name> 
    COMMAND <command> [<arg>...]
)
```

其中 `NAME` 是测试名称，在一个项目中要唯一，`COMMAND` 是测试指令

**修改已注册测试的行为与属性**

```cmake
set_tests_properties(test1 [test2...]
    PROPERTIES
        prop_name1 value1
        prop_name2 value2
)
```

`test1` 表示的 `add_test` 中的 `NAME`，可以给多个测试设置相同的属性

常用属性

| 属性名称 | 常见取值 | 作用 |
|:---:|:---:|:---:|
| `WILL_FAIL` | `TRUE`/`FALSE` | 反转测试结果，若设为 `TRUE`，当程序返回 0 时，判定为 FAIL |
| `PASS_REGULAR_EXPRESSION` | 正则表达式 | 程序的标准输出必须匹配给定的正则表达式，测试才算通过 |
| `FAIL_REDULAR_EXPRESSION` | 正则表达式 | 程序的输出匹配到了正则，测试判定失败 |
| `TIMEOUT` | 秒数（整数） | 单测试超时限制，超过特定秒数未结束则 CTest 强制终止测试并将其标记为 Timeout |
| `DISABLE` | `TRUE`/`FALSE` | 临时禁用测试 |
| `LABELS` | 标签列表 | 测试打标签，可用 `ctest -L <label>` 按标签分组运行。例如 `"unit;fast"` 等 |
| `PROCESSOR` | 核心数 | 占用 CPU 槽位数。当使用 `ctest -j` 并行测试时，告诉 CTest 该测试需要占用多少核心 |

**ctest 命令行参数**

- `--test-dir <dir>`：指定构建目录（build 目录）
- `--output_on_failure`：测试成功时保持输出简洁；仅在测试失败时才打印出包含 `std::cerr`、断言日志或报错行号的详细控制台信息
- `-V`/`--verbos`：输出详细的控制台信息，无论是否有错误，都会完整显示 `stdout` 和 `stderr`
- `-j <N>`：多进程/多线程并发执行测试
- `-R <regex>`：按正则表达式匹配名称，只运行名称符合正则表达式的测试
- `-E <regex>`：按正则表达式排除名称，忽略名字符合正则表达式的测试
- `-L <regex>`：按标签筛选
- `-LE <regex>`：按标签排除
- `--stop-on-failure`：一错即停
