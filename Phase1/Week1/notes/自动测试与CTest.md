### 输出契约

当前项目约定：

- 成功输出固定格式：`bytes=<n> lines=<n> words=<n>`。
- 成功退出码为 `0`。

### 边界值

边界值是行为发生切换的位置。与“普通文本”相比，下列输入更容易暴露实现错误：

- 0 字节文件。
- 只有一个 `\n`。
- 非空但没有末尾 `\n`。
- 只有空格、tab 和换行。
- 参数数量从 1 个变为 0 个或 2 个。
- 文件路径存在与不存在的切换。

## 3. CMake 与 CTest 的关系

- CMake 负责生成构建系统并注册测试。
- CTest 读取构建树中的测试元数据并执行测试。
- `enable_testing()` 为当前工程启用测试。
- `add_test(NAME ... COMMAND ...)` 定义测试名称和执行命令。
- `add_test()` 不会编译测试程序，测试程序仍需由 `add_executable()` 等命令创建。

最小结构示意：

```cmake
enable_testing()

add_test(
    NAME <能表达场景的名称>
    COMMAND $<TARGET_FILE:textstats> <夹具的绝对路径>
)
```

关键点：

- `$<TARGET_FILE:textstats>` 会在生成阶段得到当前构建配置下的可执行文件路径，避免硬编码 `build-gcc/textstats`。
- 测试默认工作目录通常是构建目录；夹具路径不要依赖“碰巧从哪个目录执行”。
- 可使用 `${CMAKE_CURRENT_SOURCE_DIR}` 组成源码树内夹具的绝对路径。
- 测试名称应表达行为，例如 `cli_empty_file`，不要只写 `test1`。

## 4. 断言应该检查什么

### 正常场景

至少检查：

- 退出码为 `0`。
- stdout 与完整预期格式一致。
- stderr 为空。

### 错误场景

至少检查：

- 退出码非零，而不是仅检查出现了错误文本。
- stderr 包含可行动信息。
- stdout 不含 `bytes=0 lines=0 words=0` 等伪统计。

为什么错误退出码重要：调用者、shell 脚本和 CI 通常依靠退出码判断成功或失败；只打印错误但返回 `0`，自动化系统会把失败误判为成功。

> [!note]
> CTest 默认把退出码 `0` 视为通过。测试“程序应失败”的场景时，必须让测试包装逻辑把“被测程序按预期返回非零”转换成“该测试返回 0”。不要仅把被测命令直接注册后就设置一个模糊的通过条件。

本周可选择一种简单方案，并记录取舍：

| 方案 | 适用点 | 需要注意 |
| --- | --- | --- |
| 小型 C++ 测试程序 | 可直接调用 `core` 并精确断言统计结果 | CLI 的 stderr 和退出码仍需单独验证 |
| CMake 测试脚本 | 易于启动 CLI、捕获 stdout/stderr/退出码 | 脚本中必须明确每个失败条件 |
| CTest 属性和正则 | 少量简单输出检查方便 | 不要误把“匹配到文本”等同于完整行为正确 |

## 6. 常用命令

在 `Phase1/Week1/project/` 下执行：

```bash
cmake -S . -B build-gcc -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_COMPILER=g++
cmake --build build-gcc
ctest --test-dir build-gcc --output-on-failure
```

排查时可用：

```bash
# 列出测试但不执行
ctest --test-dir build-gcc --show-only

# 输出更完整的执行信息
ctest --test-dir build-gcc --verbose

# 只运行名称匹配的测试
ctest --test-dir build-gcc -R '<测试名称正则>' --output-on-failure
```

引导：它能证明当前测试路径确实被执行，并且该类差异能被现有断言捕获；它不能证明所有实现缺陷都能被测试发现，也不能证明未覆盖输入正确。

## 8. 常见误区

- 用当前程序输出反推期望值，可能把实现缺陷写进测试。
- 测试只检查文本，不检查退出码。
- 错误路径输出了错误信息，同时仍向 stdout 输出零统计。
- 夹具文件名无法表达场景，或内容大到不能人工核算。
- 依赖当前工作目录写相对路径，换构建目录后测试失败。
- 只执行测试程序，忘记通过 CTest 验证注册是否正确。
- 测试曾失败但恢复后没有跑完整回归。
- 用 `while (!stream.eof())` 控制读取，造成末尾数据重复或状态判断错误。
