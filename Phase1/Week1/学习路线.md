# 第 1 周：Linux C++ 构建与调试基线

## 本周概览

### 所属阶段

根路线阶段 0“基线与环境”（第 1-2 周）。本周校准 Linux、Git、C++、编译链接和 CMake 基础；第 2 周将在这套构建基线上安装并验证音视频工具链。

### 这周学什么

- **Linux 命令行与文件系统**：掌握路径、权限、进程退出码、标准输入输出和常用文件操作，只覆盖完成本周项目所需范围。
- **C++ 编译与链接**：理解预处理、编译、汇编、链接四个阶段，能区分编译错误、链接错误和运行时错误。
- **多文件 C++ 基础**：使用声明与定义分离、`std::string`、`std::vector`、文件流和返回值表达一个小型程序，不提前学习复杂模板或并发。
- **CMake 与测试**：会用 target 组织可执行程序和测试，能从空构建目录完成 configure、build、test。
- **Git 与 GDB**：使用小步提交保留过程；能设置断点、单步、查看变量和调用栈，定位一个可复现缺陷。

### 本周项目

实现 `textstats`：输入一个文本文件路径，经参数校验、文件读取和统计处理，输出字节数、行数和单词数；P0 闭环为“文件路径 -> 读取 -> 统计 -> stdout”，并为路径缺失、文件不存在和空文件提供确定行为。

### 完成标准

- 能分别用 GCC 和 Clang 完成干净构建，且 `ctest` 全部通过。
- 至少覆盖 3 个正常/边界场景和 2 个错误场景。
- 能在不看答案的情况下口述一次源码到可执行文件的过程，并用 GDB 定位一个注入缺陷。
- 从新建构建目录到测试通过不超过 5 条命令；薄弱项均有证据和后续动作。

### 最终交付物

- `project/`：可构建的 `textstats` 多文件项目、测试和准确的构建说明。
- `notes/baseline.md`：C++ 自测结果、薄弱项、编译链接解释和下周阻塞项。
- `evidence/tool-versions.txt`：本周实际使用的系统、编译器、CMake、Git 和 GDB 版本。
- `evidence/build-gcc.log`、`evidence/build-clang.log`、`evidence/ctest.log`：可复核构建与测试记录。
- `evidence/gdb-session.txt`：一次缺陷定位过程及根因。

### 本周不做

不安装 FFmpeg、SDL2/Qt、OpenGL 或 Wireshark（留到第 2 周）；不学习并发、网络、包管理封装、复杂 CMake、CI 和性能优化；不追求完整单元测试框架。

## 前置检查

### 第 3 天：用 CMake 管理构建（预计 3.5 小时）

#### 今日目标

把手工构建转换为可重复的 out-of-source CMake 构建，并保持编译警告开启。

#### 学什么

- **必须掌握**：configure 与 build 的区别、source tree 与 build tree、target 及 target 级依赖。
- **必须会用**：`cmake -S -B`、`cmake --build`、`target_sources`、`target_include_directories`、`target_compile_features`。
- **了解即可**：generator、cache；不手改 `CMakeCache.txt`。

#### 怎么学

先阅读 CMake 官方 Tutorial 的入门构建部分，再把前一天的每条手工编译信息映射到一个 target 属性。使用独立的 `build-gcc` 和 `build-clang` 目录，观察 configure 阶段选择的编译器与增量构建行为。删除一个 build 目录重建，确认源码目录没有对象文件。

#### 动手任务

- 创建顶层 `project/CMakeLists.txt`，定义一个内部核心 target 和 `textstats` 可执行 target；只暴露确实需要的 include 路径。
- 使用 GCC 和 Clang 各完成一次从空目录开始的构建，处理全部项目自身警告。
- 更新 `.gitignore`，只忽略构建产物和编辑器临时文件，不忽略证据或源码。

#### 当天交付

- `project/CMakeLists.txt`：C++17、targets、include 路径与警告选项。
- `project/.gitignore`：构建目录及临时文件规则。
- `evidence/build-gcc.log`、`evidence/build-clang.log`：从 configure 到 build 的完整命令、输出和退出状态。

#### 自测问题

1. 为什么推荐 out-of-source build？
2. `PRIVATE`、`PUBLIC` include usage requirement 对依赖者有何影响？
3. 如何确认 CMake 实际使用的是 Clang 而非 GCC？

#### 结束条件

## 常见风险与降级方案

- **C++ 基础明显不足**：保留参数校验、文件读取和三项统计，不增加 P1；若仍无法独立实现，暂停路线并先补根路线建议的基础课程。
- **环境安装耗时超过 1.5 小时**：固定一个可用编译器完成 P0，保存另一编译器缺失证据，第 2 周处理环境。
- **CMake 卡住**：先保留可工作的手工构建命令，再只实现一个可执行 target；不引入库安装、package 或 generator expression。
- **测试耗时超限**：最低保留 5 个高价值场景，不引入第三方测试框架，不删除错误路径测试。
- **时间不足**：取消额外格式、彩色输出等 P1，使用第 6 天缓冲修复 P0；测试、README 和复盘不可砍。
